# 对比模式点击修复与性能调整

日期：2026-10-30。平台：Windows x86_64。

## 行为与原因

对比画布此前只在 `response.double_clicked()` 时切换缩放，单击只激活操作侧。现在单击任一侧图片即可切换适配与 100%，放大以点击处为中心；拖动释放不会切换缩放。两侧的“100% / 适配”按钮保持可用，联动继续保留相对位置和缩放比例。

## 性能调整

- 对比预览按各自画布的实际物理像素尺寸计算分档，不再沿用启动时的 2560 像素或单图模式的大预览尺寸。100% 仍使用完整分辨率。
- 后台预读完成的 Full 像素保留在有界解码队列中，只有正在放大或裁切的图片才进入主线程纹理上传。缩略图和适配预览不被等待中的 Full 结果阻塞，已有 pending 记录继续防止重复解码。
- 例如 6192×4128 RGBA 纹理约为 97.5 MiB；适配浏览时不再因预热这张图片而提前上传整张纹理。实际进入 100% 时仍须支付上传成本。

## 验证

- 修改前运行 `build.ps1 -Action test -Filter compare_single_click`，真实 egui 指针按下/释放路径失败：预期缩放 1，实际 0。
- 修改后同一测试通过，覆盖 A/B 单击、点击位置锚点、拖动释放、恢复适配、两侧实际按钮点击与预览尺寸分档。
- 队列回归覆盖 Full 延后消费、小图不被阻塞、预读结果复用、指定侧消费及 pending 清理。
- 完整 Rust 测试：265 通过，2 跳过；Clippy `--all-targets --locked -- -D warnings` 通过。目录联接测试在沙箱内因访问限制失败，沙箱外单项和完整串行重跑通过。
- 发布版使用真实 ARW / NEF 的私有副本完成原生窗口流程，旧版、新版均正常退出；新版适配、单侧 100%、联动 125% 截图已经实际查看。
- 原生窗口自动流程会主动设置缩放状态；点击行为由真实 egui 输入事件测试覆盖。本次没有取得对用户当前窗口进行桌面点击的 Computer Use 访问权限。

单次原生流程耗时：旧版 15866 ms，新版 15789 ms。流程含固定等待和截图，此差异不能证明整体提速。单次首图日志为旧版 115.6 ms、新版 74.6 ms，亦受缓存与运行顺序影响，不作为稳定加速比例。
