# 照片格式：2.4.0

2026-10-24 补充：独立的 [RAW 编辑工作区](RAW-EDITING.md) 支持 ARW/NEF/DNG 的 Adobe 完整显影、曝光和白平衡，DNG 明确保存时额外同步内嵌 XMP。下文关于只写旁车、LibRaw 色彩和快速预览的说明适用于普通选片路径。

旧 NEF 没有输出区域标签时，仅允许每轴不超过 64 像素、同时不超过 1% 的传感器边缘差异，使用相机记录的近全尺寸预览尺寸作为显示区域。该规则不放大预览；100% 始终对应实际解码像素，较小预览仍进入 RAW 回退。

当前启用 Sony ARW、Canon CR2、Nikon NEF、DNG、JPG/JPEG（包括 `.jpe`），扩展名不区分大小写。Bridge、Lightroom、独立文件/目录入口采用同一支持范围。混入 CR3、RAF、其他 RAW、PNG、视频和旁车时跳过这些文件。存在支持的照片时正常打开，全都不支持时才报告没有可加载照片。支持格式中的损坏文件或不可用解码器按照片显示错误，其他照片仍可浏览。

DNG 使用独立的有界 TIFF 随机读取器，支持大小端和远处的 SubIFD，以实际 JPEG 像素尺寸选择预览。网格和胶片带先读取内嵌小 JPEG 或 RGB8 缩略图占位，随后升级为 200 像素预览；适屏使用最大预览，100% 交由 LibRaw 检查是否需要传感器解码。没有独立 JPEG、预览损坏或特殊布局时使用 LibRaw 兜底，RGB8 小图仍可独立显示。内嵌 XMP 可用于载入评分、标签、曝光和裁切；已有旁车优先，首次保存以内嵌 XMP 为模板写入同名 `.xmp`，不改写 DNG。LR 插件通过既有同步接口回写目录；Bridge/ACR 对 DNG 外置旁车的识别需由宿主验证，不等同于修改 DNG 内嵌元数据。性能和验证范围见 [DNG.md](DNG.md)。

ARW 保留既有有界 TIFF 快速读取。CR2/NEF 使用 [LibRaw 0.22.2](https://www.libraw.org/download) 原生模块：普通浏览提取最大可用内嵌预览，按像素尺寸选择，不能用压缩字节数代替分辨率。进入 100% 时，有全尺寸预览直接解码 JPEG；预览不足才在后台解码 RAW。采用厂商有效图像区域和 EXIF 输出尺寸，排除传感器边缘；不会把小预览插值放大称作原始分辨率。该分支的去马赛克、相机白平衡和 sRGB 输出由 LibRaw 提供，颜色与机内 JPEG 或 Lightroom 显影可能不同。

JPG 直接解码原图。RAW 的评分/曝光/标签仍写入同名 XMP 旁车；JPG 写入标准内嵌 XMP，更新已有 EXIF 方向时只改方向字段，不重压缩图像，不改其他 EXIF/ICC 数据。已有扩展 XMP、多重标准 XMP 或损坏元数据会保留原文件并拒绝编辑，报错可见。标准 APP1 XMP 包上限 64 KiB；JPEG 文件上限 128 MiB，图像解码上限 160 MP。

Bridge 文件移动覆盖这些启用格式。JPG 自身携带元数据，不读取、移动或覆盖同名 RAW 的 `名称.xmp`/`名称.acr`；仅完整文件名形式的 JPG 旁车（如 `照片.jpg.xmp`）随 JPEG 同行。RAW 保持原有旁车关联。LR 继续保存整理计划，实际移动由宿主完成，保留目录记录与历史。

须保留 `fastcull.exe` 邻近的 `fastcull_raw.dll`。两者使用静态 CRT。LibRaw 上游源码压缩包、许可证、适配层源码和重建脚本随分发包提供；源码包 SHA256 固定为 `f4448371523f9960d26a131ed9dc21bee49f967adbcc4fb6f56b9b47c2ba87c6`，重建使用 Visual Studio C++ Build Tools。普通用户不需要编译。

当前验证使用 Canon EOS 5D Mark II CR2、Nikon D3S NEF、私有 JPG 及仅改变 CR2 内嵌大预览的测试副本，覆盖原始分辨率、内嵌预览不足时回退、像素流保留、方向、评分清零、手动 LR 读取和 RAW/JPG 同名移动。验证记录见 `formats-validation-2.4.0.json`；不能据此声称所有 CR2/NEF 相机机型均已实测。
