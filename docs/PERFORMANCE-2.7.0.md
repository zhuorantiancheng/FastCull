# 2.7.0 性能验证

2026-10-14，在同一台 Windows 电脑上对照保留的 2.6.1 和 2.7.0。界面布局、快捷键、评分、曝光、对比联动、照片移动及退出同步规则保持不变。

## 实测结果

| --- | ---: | ---: |

## 实现

- 字体读取与图形窗口初始化重叠；照片列表后台加载不再额外等待两帧。
- 缩略图和适屏 JPEG 在适用时使用 Windows 自带 WIC 的 1/2、1/4、1/8 缩小解码。只使用微软 JPEG 编解码器，失败或不适用时回退 Rust；CMYK 等保持原解码路径。[微软原生缩放说明](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/nf-wincodec-iwicbitmapsourcetransform-getclosestsize)
- 适屏图按实际画布物理像素加 25% 余量，在 1024～4096 长边间按 256 像素分档；窗口变大时补读更清晰的预览，较晚到达的小图不能覆盖已有的大图。
- 不透明照片缩图跳过 alpha 预乘和反乘；转成显示像素的工作移至后台，减少主线程大内存遍历。
- 切图取消排队中的过时工作，保留当前图、邻近图和参考图的在途结果并去重。用户重试会取消旧结果；邮箱仍有界，当前图优先。
- 适屏图可见且停留约 300ms 后预热当前全尺寸图，只用后台解码线程。预留的主图线程继续服务新照片；快速翻片、网格、对比模式不新增此类预热。
- 元数据首次探测按照片合并，有序索引队列替代重复全表搜索；筛选统计只计算展开分组，并在照片数据、条件或文件夹范围变化时失效。

未增加常驻服务、开机启动项、照片磁盘缓存或新的运行时安装依赖。预热会增加后台读取，内存继续受既有纹理缓存策略管理；缓存预算不等于进程总内存上限。

## 正确性与界面检查

- 107 项 Rust 测试通过，包括真实 CR2/NEF、评分、移动、对比、相对位置和缩放回归；14 项 Bridge 脚本测试通过。
- 48 项 Python/Lua 测试：47 项通过，1 项原生 GUI 可选测试在默认套件中跳过，随后单独启用并通过。此往返使用 SDK 测试替身和真实 exe，不代表本轮在真实 Lightroom 目录里操作过。
- Clippy 所有目标无警告。
- ARW、CR2、NEF 全尺寸内嵌预览内容的 SHA-256 与旧版一致，尺寸分别为 6192×4128、5616×3744、4256×2832；按每份文件检查有效尺寸的传感器解码回退保留。
- 缩小解码与完整 JPEG 解码后双线性缩图对照，样片 RGB 平均绝对误差为 0.21～0.91（0～255），alpha 全为 255；缩小解码与原缩图不是逐像素相同，但不影响 100% 路径。
- 原生截图复核默认、800×600、640×480、网格、对比、曝光、筛选及关闭确认；180 次快速切换压力回归见原始记录。

可重复解码基准为 `examples/decode_bench.rs`，侧栏基准为 `examples/filter_bench.rs`。构建 release example 后，把同版本 `fastcull_raw.dll` 放到生成的 example exe 旁，再运行 `decode_bench <照片路径> 7`；`filter_bench` 无参数。照片样本和中间截图不随程序打包，正式包不依赖临时目录。
