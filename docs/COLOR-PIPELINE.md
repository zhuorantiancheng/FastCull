# RAW 色彩管线与校准

2026-10-30 的改动解决了提前编码为 8 位 sRGB、缺少 DCP 外观处理和两套白点标度的问题。已有 ARW/NEF 样本对留存 ACR 参考的误差明显降低；这些样本用于检查实现方向，不代表所有相机、光源与 Lightroom 配方均已匹配。

## 处理顺序

1. LibRaw 解包与去马赛克，输出 16 位线性相机 RGB；按实际白平衡增益归一尺度还原为浮点，保留高光余量。
2. 原片白平衡直接保留相机增益。自定义 K/Tint 使用原生与 Rust 共用的 Robertson 等温线模型，并按机型 DCP 色彩矩阵求相机白点。
3. 选择机型 DCP，在倒数色温上插值；处理匹配签名的校准矩阵、AnalogBalance、ForwardMatrix 或矩阵回退，再转换到 D50 ProPhoto。
4. 应用随光源插值的 Hue/Sat 校正。裁切、旋转与输出缩放在浮点数据上合并采样；灰点采样保留在配置文件处理之前。
5. GPU 应用绝对曝光、基础色调、DCP Look、高光肩与色调曲线，再调整自然饱和度/饱和度，转换为 sRGB 并在显示末端编码。

HSV 表按饱和度最快存储，色相环绕、三线性插值；sRGB 编码标签作用于明度查表，不先编码三个 RGB 通道。显式 DCP 曲线用单调插值；没有显式曲线时使用本地经典 SDR 基线。该基线来自公开 Adobe DNG SDK 默认曲线的 11 个稀疏数值点，并非当代 Lightroom 默认渲染的完整复刻。[Adobe 原始渲染源码镜像](https://raw.githubusercontent.com/LineageOS/android_external_dng_sdk/lineage-22.2/source/dng_render.cpp)

曝光只在显示配方中应用一次。CPU 数值验收与直方图使用同一组显示公式；正式窗口由 GLSL 执行。线性缓存保留 float32 像素、Look、曲线、曝光基线和相机灰点采样，读取时验证尺寸、有限值和配置文件指纹。

## 配置文件与回退

默认查找匹配机型的 Adobe Standard DCP。XMP 请求的 DCP 可用时使用该文件；Adobe Color 等增强 XMP 配置文件、找不到的文件或机型不匹配不能假装已执行，界面显示实际结果与回退原因。原始配方名称及未支持设置仍保留供 LR/ACR 使用。

搜索范围和环境变量见 [RAW 编辑说明](RAW-EDITING.md)。配置文件属于本机资源，未复制进发行目录；没有 DCP 时使用 LibRaw 相机矩阵与本地色调。完整 DNG 内嵌校准配置、DefaultBlackRender 的全部处理、增强 XMP 配置文件、蒙版和当前 Adobe 处理版本的局部/基础算法仍有实现缺口。

## 验收范围

使用 Sony ILCE-6700 ARW、Nikon D3S NEF 与 DxO 输出 DNG，在 5500 K / Tint 0 和 7500 K / Tint 20 下，与 2026-10-24 留存的真实 ACR sRGB 输出按相同统计方法对照。参考图当时的准确配置文件名称未记录，不能用该对照证明指定 DCP 与 Lightroom 像素等价。没有按单张照片拟合曝光补偿。

统计采用统一 192×128 采样图，RGB MAE 单位为 0–255 码值；亮度偏差为有效像素的线性亮度比 log2 中位数。MAE 同时受到亮度、颜色、采样和细节影响，不是感知色差 ΔE。完整数值见 [校准验证 JSON](raw-color-calibration-validation-2026-10-30.json)，改动前的单因素调查见 [调查记录](RAW-COLOR-INVESTIGATION-2026-10-30.md)。

本轮只运行离线测试与数值分析，检查原 RAW 哈希、缓存逐位往返、曝光方向、白点求解、取消恢复和旧接口兼容。GLSL 通过桌面 OpenGL 3.3 语义的离线编译/链接；未运行真实 GPU 窗口验收。依用户要求，桌面显示、滑杆手感和具体照片颜色由用户实测。macOS 尚未实机验证本轮改动。

下一步精细校准应固定相机、光源、LR 版本、ProcessVersion、配置文件及所有滑块，取得用户实际 ARW/NEF 的同尺寸 sRGB 导出；以灰卡/色卡和独立场景分别检查中性轴、肤色、高饱和度及高光，再用未参与调参的照片验收。显示器色彩管理与画面统计应分别验证，避免把屏幕外观差异混入 RAW 算法修正。
