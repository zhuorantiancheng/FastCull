# RAW 编辑颜色差异调查（2026-10-30）

ARW、NEF 与 Adobe 的差异已在进入窗口前的 RGB 像素中复现。当前本地显影只完成相机矩阵、白平衡、曝光和 sRGB 转换，缺少 Adobe 配置文件和默认色调处理；另有可明确定位的 K/Tint 标度差异。缩放已经实现，本次没有将颜色调成一个未经验证的“LR 匹配”外观。

## 对照方法与实测

本次重新调用安装目录中的 `fastcull_raw.dll`，只读打开三张留存 RAW，设置 EV=0、Custom WB；对照 2026-10-24 留存的真实 Camera Raw sRGB PNG。参考图由当时的 Photoshop/Camera Raw 后端生成，不是本次从 Lightroom 目录重新导出的结果，也没有指定当前用户在 LR 中使用的配置文件。因此它能复现引擎差异，不能替代用户实际目录的色彩验收。

处理方向后，将本地结果缩放到参考图尺寸，统一降采样到 192×128 统计。亮度使用 sRGB 逆传递函数得到线性 RGB，再计算 Y=0.2126R+0.7152G+0.0722B；报告双方 Y 均处于 0.015–0.9 区间的 `median(log2(Y_Adobe / Y_local))`。正数表示参考图较亮，属于画面统计差异，不能作为应写入 XMP 的曝光修正。

| 样本 | WB | 本地较暗的中位亮度差 | RGB 平均绝对差（0–255） | 仅对齐亮度后的剩余 RGB 差 |
| --- | --- | ---: | ---: | ---: |
| ARW | 5500 K / 0 | 0.714 EV | 20.70 | 7.94 |
| ARW | 7500 K / 20 | 0.776 EV | 23.58 | 8.96 |
| NEF | 5500 K / 0 | 0.440 EV | 5.15 | 6.65 |
| NEF | 7500 K / 20 | 0.469 EV | 5.91 | 6.42 |
| DxO DNG（补充样本） | 5500 K / 0 | 1.109 EV | 31.93 | 7.67 |
| DxO DNG（补充样本） | 7500 K / 20 | 1.130 EV | 34.85 | 7.20 |

“仅对齐亮度”将本地线性 RGB 统一乘以上述 EV 对应的增益，再编码回 sRGB。它不是重新显影，也不包含传感器高光恢复。NEF 的误差反而增大，ARW/DNG 对齐后仍明显非零，说明统一加曝光不能解决全部差异。RGB 绝对差不是色卡 ΔE，也未声称这些数值能代表所有机型。

## 已定位的代码路径

1. **配置文件与默认色调缺失。** `src/local_raw.rs::render` 只把输出尺寸、温度、Tint、曝光传给原生层；`native/raw_bridge.cpp::fc_raw_develop` 输出相机矩阵转换后的 sRGB。`CameraProfile`、DCP Hue/Sat 表、Look 表和配置文件曲线不进入显影。`src/raw_preview.rs` 的七项调节采用本地公式，中性参数时基本保持原像素，也不会补上 Adobe 默认曲线。Adobe 的说明确认配置文件能改变颜色与明度而不改变滑块值；所以“所有滑块相同”不足以得到相同画面。[Adobe 配置文件说明](https://www.adobe.com/learn/lightroom-cc/web/photo-filters)。
2. **K/Tint 的数值合同没有对齐。** 本地 `temperature_uv` 使用黑体轨迹多项式，`wb_multipliers` 沿局部法线偏移 `Tint × 0.0001`。Adobe 公开 DNG SDK 的 `dng_temperature` 使用表格及等温线插值，其 Tint 距离标度为 `1/3000`。仅距离量级就相差约 3.33 倍，尚未计入轨迹、方向和相机矩阵差异。这是实在的模型不一致；但不能仅将常数乘以 3.33 就声称复现 LR。[Adobe DNG SDK 入口](https://www.adobe.com/support/downloads/dng/dng_sdk.html)、[Adobe 原始源码的覆盖率镜像](https://storage.googleapis.com/oss-fuzz-coverage/dng_sdk/reports/20260920/linux/src/dng_sdk/source/dng_temperature.cpp.html)。
3. **DNG 矩阵流程还有额外差异。** 本项目使用的 LibRaw 0.22.2 在 `src/metadata/identify.cpp` 选择 D65/日光色彩矩阵，没有在本地编辑器中实现随白点变化的双光源配置文件插值。补充 DNG 含两组矩阵和 BaselineExposure=0.1 EV；该标签在此版 LibRaw 源码中被读取，但本地显影没有消费它。这不足以单独解释实测约 1.1 EV，且不能用于解释 ARW/NEF 的全部差异。
4. **显示端仍有独立边界。** 原生输出明确设置 sRGB 传递函数（1/2.4、12.92）；PNG 标记 sRGB，GPU 在调节前后做相应线性化与编码。本次差异在未经过 GPU 和显示器的输出中已存在，因此显示器不能解释全部问题。不过当前 egui/Glow 路径未实现应用级显示器 ICC 转换；LR 的显示色彩管理可能额外扩大实机差距。本次没有测量当前屏幕 ICC、Windows 自动色彩管理或 HDR 状态。[LibRaw 参数说明](https://www.libraw.org/docs/API-datastruct.html)、[Lightroom 色彩管理说明](https://helpx.adobe.com/lightroom-classic/desktop/workspace/color-management.html)。

这里能确认“本地显影缺少哪些处理”和“同参数输出确有差异”，尚未通过单变量替换分别量出配置文件、WB 和曲线各自占多少。现有证据未发现传感器压缩数据解包损坏；也不能据此证明所有机型的解码都没有问题。

## 修复顺序与本次交付

建议后续按 **统一白点和 Tint 的数学定义 → 相机配置文件及色调曲线 → 显示器 ICC** 逐层建立对照，继续保留本地显影，不恢复 Adobe 软件依赖。先以用户实际 ARW/NEF、当前 LR 配置文件和同配方 sRGB 导出建立基准，再验证跨机型改进。8 位 sRGB 上的七项 GPU 公式也需要单独校准，尤其是高光与阴影，不能只校准一张照片。

本次交付缩放、平移和按需全尺寸加载，并把界面中的配置文件名称明确标为“仅保留”，以免误认为已执行 Adobe 配置文件。色彩算法本次保持原状；颜色调查不代表颜色匹配已修复。未调用 Adobe 显影，未修改用户原片，临时对照只读取留存样本并核对读取前后 SHA256。

机器可读结果见 [raw-zoom-color-validation-2026-10-30.json](raw-zoom-color-validation-2026-10-30.json)。临时对照脚本、图片及构建日志位于 `.agent-temp/2026-10-30-raw-zoom/`；正式程序不依赖该目录。

## 后续单变量调查：ARW / NEF

用户确认后续自行进行桌面验收。本节只运行原生数值实验、读取本机配置文件和检查源码；没有启动 Adobe 应用，也没有进行桌面检查。生产 EXE、DLL 和颜色算法均未修改。

实验针对留存的 **Sony ILCE-6700 ARW** 和 **Nikon D3S NEF**，各测试 5500 K / Tint 0、7500 K / Tint 20。诊断 DLL 从当前 `native/raw_bridge.cpp` 构建，切换每个实验时重置解包缓存。四组基线都先与安装 DLL 输出核对像素 SHA256，完全相等，再进行修改，防止把诊断程序本身的差异误判成算法效果。原片均只读，批次结束核对 SHA256。

### 日光矩阵实际相同，配置文件远不止矩阵

只读解析本机 `%PROGRAMDATA%/Adobe/CameraRaw/CameraProfiles/Adobe Standard/` 下对应机型的 DCP 后，发现：

| 项目 | Sony ILCE-6700 | Nikon D3S |
| --- | --- | --- |
| LibRaw `cam_xyz` 与 DCP `ColorMatrix2` 的最大绝对差 | 5.47×10⁻⁸ | 4.02×10⁻⁸ |
| 标定光源 | A（17）、D65（21） | A（17）、D65（21） |
| 前向矩阵 | `ForwardMatrix1/2` 均有 | `ForwardMatrix1/2` 均有 |
| 色相／饱和度／明度校正表 | 两组 90×30×1 | 此文件没有 |
| Look 表 | 36×8×16 | 36×8×16 |
| 文件内显式 `ProfileToneCurve` | 没有 | 没有 |

A6700 两组校正表各有 2700 个三元组，其中 2694 / 2697 组不等于恒等变换；第二组饱和度增益最高约 1.86、明度增益最高约 1.78。两台相机的 Look 表也有大量非恒等项，色相偏移的全表范围约为 ±18.48°。这些是配置文件表格的极值，不代表当前照片每个像素都受到同样幅度的调整，也不能直接当作滑杆修正。

因此，这两张样本不支持“没有正确的日光相机矩阵”作为主要解释。当前本地流程实际没有读取和执行上述配置文件的表格、前向矩阵及光源插值。即使相机型号和一个 3×3 矩阵相同，完整显影仍可能不同。参考 ACR 输出当时使用的具体配置文件名称没有留存；不能据此声称这些 Adobe Standard 表格就是参考图中全部差异的来源。

### 单独修 Tint 或解码质量，不能消除差异

24 组实验包括四组设置下的生产基线、仅修改 Tint 标度、使用公开等温线白点模型、仅选择 AHD、仅禁用半尺寸、仅禁用嵌入矩阵。

| 实验 | 结果 | 能支持的判断 |
| --- | --- | --- |
| Tint 标度由 1/10000 改为 1/3000，Tint=0 | 像素完全不变 | Tint 标度不解释中性 Tint 下的差异 |
| 换用公开等温线白点模型，Tint=0 | 相对生产输出平均差：ARW 0.061、NEF 0.036（0–255） | 这两个色温下轨迹近似的影响很小 |
| 仅改 Tint 标度，7500 K / 20 | ARW 对参考 MAE 23.58→22.57；NEF 5.91→5.80 | 有小幅 RGB 均值改善，不能认为已匹配 |
| 同上，独立检查归一化线性 RGB 色度误差 | ARW 0.04507→0.03726；NEF 0.03500→0.04054 | NEF 色度反而变差，缺乏可跨机型交付的改善证据 |
| 仅禁用半尺寸 | 相对生产输出平均差：ARW 约 0.74–0.75、NEF 约 0.21–0.22（0–255） | 会影响细节与采样，但不足以解释当前整体差距 |
| 半尺寸开启时仅将质量改成 AHD | 像素完全不变 | 半尺寸路径下不能靠改插值质量开关解决颜色 |
| 仅禁用嵌入相机矩阵 | 像素完全不变 | 这些样本没有体现该开关造成的色差，不能推广到所有 RAW |

色度误差将线性 RGB 除以各像素 R+G+B，在原亮度掩码范围内统计平均绝对差，从而减少统一亮度增益的影响。它不是感知 ΔE，暗部、剪切和采样仍会影响统计。

另做 8 组矩阵实验：从 16 位线性、已白平衡的相机 RGB 重建当前矩阵输出，平均误差为 0.23–0.36 个 8 位码值（原生整数 LUT 与浮点 sRGB 及重采样存在差别）；随后只换为固定 DCP `ForwardMatrix2`，经 D50→D65 Bradford 适应后转为 sRGB。该单独替换使 ARW 的参考 MAE 增大，NEF 几乎不变。这个试验没有实现完整 DCP 白点适应、插值、校正表、Look 表和色调处理，不能用来判断完整 DCP 无效；它说明“拿到一个矩阵直接替换”也不足以构成修复。

### sRGB 目标和零滑块值，都不定义唯一外观

Adobe 公开 DNG SDK 的渲染路径先进入 ProPhoto 工作空间，再处理随白点选取的 Hue/Sat 校正、曝光／暗部、Look 表和色调曲线，最后转换输出色彩空间。旧 SDK 的场景参照默认设置会使用 ACR3 默认曲线，配置文件有有效曲线时再覆盖。因此，本机这两个 DCP 中没有 `ProfileToneCurve` 标签，并不意味着 Adobe 渲染采用恒等曲线。[Adobe 原始渲染源码（覆盖率镜像）](https://storage.googleapis.com/oss-fuzz-coverage/dng_sdk/reports/20260920/linux/src/dng_sdk/source/dng_render.cpp.html)。

这是公开 DNG SDK 的流程证据，不是对当前 Lightroom ProcessVersion 算法的完整复原。它明确解释了为何“输出都叫 sRGB、曝光都是 0”仍不足以得到同一画面。

当前代码在这些步骤之前便转成 8 位 sRGB 并剪切范围，再在 GPU 上调高光、阴影等；被提前剪切的高光或色域信息无法由后续滑杆恢复。后续实现完整本地颜色流程，需要从高精度线性相机数据衔接配置文件处理，把显示编码和降到 8 位放在末端，同时校准现有 GPU 调节。没有证据支持用统一提亮、硬改 Gamma、只乘 Tint 常数或单独替换矩阵作为通用修复。

这轮把原因进一步收窄到显影处理差异，但尚未取得 Adobe 的未处理传感器数组或各处理中间缓冲，不能严格证明两引擎的传感器解包逐点相同，也不能量化每个缺失步骤对总误差的占比。

完整数值和配置文件摘要见 [raw-color-experiments-2026-10-30.json](raw-color-experiments-2026-10-30.json)。配置文件只记录摘要和哈希，没有复制或分发本机 Adobe DCP 文件。诊断 DLL、脚本及完整实验数据放在 `.agent-temp/2026-10-30-raw-color/`；它们没有替换安装目录中的 DLL。
