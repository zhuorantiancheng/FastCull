# FastCull 2.7.4：100% 切图过渡修复

验证日期：2026-10-14，Windows x64。

## 原因与修复

切图保留了缩放状态和相对位置，但绘制代码要求全尺寸纹理已经加载才能使用放大倍率，因此下一张的适屏预览会先按适屏显示。

解码器现在提前报告实际使用的全尺寸图像宽高。单图和对比模式将缩略图、适屏预览绘制到全尺寸图像对应的同一个矩形，最终纹理到达时只更新清晰度。宽高来自实际 JPEG 头或原生位图，不通过扩展名、传感器尺寸或上一张照片推断。尺寸尚未知时显示加载提示，避免插入适屏画面。

## 验证

- 修改前，新增渲染回归测试复现了下一张先显示适屏画面的问题；修改后通过。
- 110 项 Rust 测试通过，Clippy 全目标检查无警告；Bridge JavaScript 16 项测试通过。
- 渲染测试覆盖单图和对比模式、两种图像尺寸、横竖方向以及 100%、150%、200% 屏幕缩放，验证缩略图、适屏预览、全尺寸纹理三个阶段的绘制矩形一致。
- 工作线程测试验证全尺寸几何信息能在 UI 消费解码像素前取得。
- 在真实桌面使用 ARW、CR2、NEF 样片副本完成应用内原生冒烟测试，生成 13 张截图，结果 `error=None`；检查了 100% 画面和对比画面截图，联动相对位置检查通过。

## 边界与交付

加载延迟取决于图像与磁盘；本修复消除过渡阶段的倍率跳变，不保证任何照片都能立即显示清晰图。原生截图检查用于确认最终画面和交互，过渡矩形一致性由逐阶段渲染测试验证。本次没有重新执行全部 Adobe 宿主安装流程。

正式程序位于 `lrplugins/FastCull.lrplugin/`，分发包位于 `dist/public-2.7.4/`。可重建测试日志、截图和样片副本位于 `.agent-temp/2026-10-14-zoom-transition/`，程序和分发包不依赖这些中间文件。
