# 退出选片器时同步到 Lightroom

更新整个 `lrplugins/FastCull.lrplugin` 目录后，关闭旧选片窗口并重启 Lightroom，确保 Lua 模块与 `fastcull.exe` 同时更新。从 LR 打开选片器，退出时选择 **同步全部并关闭**，LR 后台自动处理本次修改的星级、色标、旗标、曝光、裁切（含角度和重置）及 90° 旋转。成功后不再弹成功确认；失败会显示原因并保留待同步会话。

**仅关闭，稍后同步** 保留 XMP 与会话记录；之后使用插件菜单 **同步选片会话（仅修改过的字段）**。**取消** 返回选片，不发起同步。裁切面板的未应用草稿需要先应用才能成为已保存修改。自定义比例预设是选片器偏好，不属于某张照片的 LR 显影记录；同步的是应用后的矩形和角度。

## 同步范围与失败恢复

- 使用启动时保存的目录身份与原照片 UUID/路径定位，即使 LR 当前选区改变也不会改到新选区。虚拟副本按原选中 UUID 处理，但共用物理文件的副本仍共用 XMP。
- 只发送本次实际修改的字段；曝光只更新 `Exposure2012`，裁切只更新裁切参数，保留曲线、对比度等其他显影设置。写入裁切矩形时解除已有 LR 比例约束。重试时先比较当前参数，已达到目标的曝光与裁切跳过显影写入，减少重复历史步骤。
- 旋转先读当前 LR 方向，再到达 XMP 中的绝对目标方向。若旋转后裁切写入失败，重试只补未达到的方向，不重复叠加 90°。曝光、裁切与旋转在目录事务完成后回读；结果不符时不确认同步完成。
- 自动和手动同步共用队列，完整执行一次读取、写入及进度确认后才处理下一次请求，防止旧快照覆盖新修改。手动同步当前选区时，在提交请求时记录选区；排队后切换选区不会改到其他照片。目录切换则保留原会话并提示稍后重试。
- 退出监听与曝光基线读取分别运行，不必等所有照片显影参数读取完才开始检测退出请求。
- Lightroom Classic **11.4 或更高版本**才能执行自动旋转。旧版 SDK 的旋转方法可能作用于无关选区；Adobe 确认在 11.4 修复，见 [SDK 旋转问题与修复记录](https://community.adobe.com/bug-reports-674/p-sdk-photo-rotateleft-and-rotateright-can-rotate-all-photos-in-the-catalog-663142)。旧版本若当前方向已等于目标仍可同步其余修改。
- LR 与 XMP 镜像状态不同、缺少原照片、旁车损坏、目录写入失败或回读不符时，错误会显示且未完成会话继续保留。确认原因并修复后，从同步菜单重试；已成功的绝对值再次应用不会叠加。
- 有整理计划时先同步编辑，再建立待整理分组；实际文件移动仍在 LR 文件夹面板完成。选片器不会在 LR 外搬走目录中的原文件。

## 协议与验证

V3 会话为评分、标签、旗标、曝光、裁切、绝对方向分别记录修改修订号，继续读取旧 V1/V2 会话。旧“只同步星级”进度不会确认裁切或方向。退出收据沿用 `.stars-request` 文件名以兼容旧入口，新收据第二行固定为 `all`，不再依赖是否存在整理计划。扩展桥接行使用 `ROW_V3`；旧插件不能静默忽略新增字段后确认成功，升级时应整体替换插件。

`tests/session_edits.rs` 检查新字段修订、裁切重置、缺字段失败和普通退出收据。`tests/test_bridge.py` 通过实际 Rust CLI 与 SDK 形状的 Lua 模拟验证自动退出、原选区定位、旧协议、字段保留、八种方向的旋转、部分失败重试和回读失败。原生窗口测试验证关闭界面及退出收据。

上述自动化不等于真实 Lightroom 宿主验收。需在宿主中核对一张普通照片与一张竖幅 RAW 的裁切/角度/旋转，再确认曝光与评分同步、其他显影设置保留。选片器仍使用照片预览，无法复现 LR 的完整 RAW 显影、镜头及透视校正。
