# FastCull RAW/JPEG 2.7.0 — Rust 选片器

当前源码提供按需 **独立 RAW 编辑窗口**：选中 ARW、NEF 或 DNG，点击左侧入口，加载 RAW/XMP，通过本地 LibRaw 与 GPU 模型显示 sRGB 预览。可编辑曝光、白平衡和对比度、高光、阴影、白色、黑色、自然饱和度、饱和度，并用灰点吸管估计白平衡。无需安装或启动 Adobe 软件，主窗口仍可选片；从 LR 打开时可按需读取已运行目录中的完整显影配方。

本地显示不重现 Adobe 的 DCP Look、曲线和蒙版算法，这些内容保留在 XMP 中；色温/Tint 使用本地模型，不承诺与 LR/ACR 同参数像素等价。适屏先显示快速预览，再后台显影至最多 1600 像素，全尺寸按需加载。保存、性能和当前验收记录见 [RAW 编辑说明](docs/RAW-EDITING.md)；下文 2.7.0 的历史性能数据不用于衡量这套新管线。

当前源码已增加 **DNG** 支持，独立入口、Bridge 与 Lightroom 入口均可打开；DNG 使用内嵌 JPEG 快速预览和 LibRaw 兜底，支持载入内嵌 XMP、保存旁车。旧版压缩包不包含本次新增功能，构建与实测范围见 [DNG 支持与性能](docs/DNG.md)。

> 面向其他用户的最新 Windows 2.7.1 安装包与便携包见 [README](README.md) 和 [发布说明](docs/DISTRIBUTION.md)。本文保留 2.7.0 功能与性能说明。

2.7.0 优化启动与预览管线，界面和快捷键保持不变。当前照片停留约 300ms 后后台预热 100%，切图复用仍相关的解码结果；缩略图和适屏图使用 Windows 原生缩小解码，遇到不支持的 JPEG 自动回退。实测方法与限制见 [性能验证](docs/PERFORMANCE-2.7.0.md)。

界面采用深灰背景、淡蓝选中态与图标导航；增加控件留白和字号，筛选默认展开星级，其余分组按需展开。窄窗口自动使用紧凑工具栏。快捷键、点击定位放大及照片整理流程保持一致。

左侧活动栏提供“文件夹”“筛选”和“裁切”，默认打开筛选面板；再次点击文件夹或筛选入口可收起，Ctrl+F 切换筛选，裁切快捷键为 T。文件名和 ISO / 光圈 / 快门 / 焦距位于右上角，相机、镜头和拍摄时间通过悬停查看。底部查看模式按钮为 E（单图）、G（网格）、C（对比）。单图点击、对比双击放大时，以点击的照片位置为查看中心。

100% 放大浏览时，方向键、缩略图点击及栏内滚轮切换照片会保留当前相对查看位置；位置按旋转后的图像尺寸计算，适应不同分辨率和显示缩放。对比模式保留各自视图的缩放与偏移。超出新照片可显示范围时限制到边界，重新切换适应/100% 或旋转当前照片仍会居中。

底部缩略图栏：拖动上边缘调整大小，缩略图宽度随栏高同步缩放。鼠标停在栏内滚动可快速切换当前筛选结果中的照片（向下下一张，向上上一张）；拖拽照片、调整栏高和打开对话框时暂停滚轮切图。

胶片带和网格按缩略图自身比例显示，不随大图缓存加载改变大小。Sony TIFF 预览路径使用中等内嵌预览缩小生成缩略图，避免相机小图的填充黑边；实际横竖方向与裁切比例仍会影响画面占用尺寸。

主图及对比视图的适屏布局提前读取原图宽高，预览升级时保持相同的画面边界和裁切坐标，避免不同级别预览的比例与像素取整造成轻微伸缩。Sony RAW 优先使用 EXIF 原图尺寸，缺失时读取内嵌 JPEG 头部；JPG 使用实际 JPEG 尺寸，其他 RAW 使用原生元数据。100% 显示仍以实际解码像素为准。

Bridge 与 Lightroom 现可使用 **Ctrl + Alt + K** 打开选片器。更新后重启 Bridge、重新载入 LR 插件。快捷键仅在对应宿主前台生效，见 [快捷键说明](docs/HOTKEYS.md)。

在 Lightroom Classic 或 Adobe Bridge 中打开 ARW、Canon CR2、Nikon NEF、JPG/JPEG，快速浏览、打星、加色、拾取或拒绝，再同步回 Lightroom。选片器以 Rust 实现，CR2/NEF 使用随插件提供的 LibRaw 原生模块；用户运行 Windows x64 插件无需 Python、Pillow 或 Imaging Edge。其他 RAW 格式暂未启用，按用户要求留待后续检查。

## 安装与升级

1. 解压 `dist/FastCull-Rust-2.7.0-win64.zip`，将整个 `FastCull.lrplugin` 文件夹放到长期保存的位置，保留 `fastcull.exe`、`fastcull-keys.exe` 和 `fastcull_raw.dll`。使用项目内插件时，在 LR 增效工具管理器重新载入插件。独立使用可选择 `dist/FastCull-Windows-2.7.0-win64.zip`，见 [独立版说明](docs/STANDALONE.md)。
2. Lightroom Classic → 文件 → 增效工具管理器 → 添加该文件夹。已有插件可重新加载。
3. 默认使用插件内的 `fastcull.exe`。旧版默认 Python 脚本路径会自动升级；若之前填了自定义路径，请在设置中改为新 exe，或清空让它重新探测。

也可以直接使用本项目中的 `lrplugins/FastCull.lrplugin/`。运行要求：Windows 10/11 x64、可用的 OpenGL 3.3 图形驱动；Rust 与原生模块均使用静态 CRT，无需额外安装 VC 运行库。源代码在 `src/` 和 `native/`。Python 原型仅保留原有 Sony ARW 功能，多格式功能使用原生 exe。

RAW 普通浏览优先使用最大的内嵌预览；100% 优先使用全尺寸内嵌 JPEG，没有足够分辨率时才解码原始像素。按相机有效图像区域和 EXIF 输出尺寸判断，避免传感器边缘造成无谓的完整解码。JPG 直接使用原图，评分等修改写入内嵌 XMP，保留压缩图像数据；旋转同时更新已有 EXIF 方向。具体支持范围、存储规则及验证见 [多格式说明](docs/FORMATS.md)。

## Adobe Bridge 与快捷入口

混合选择跳过视频、旁车、PNG 和未启用的 RAW 格式，加载 ARW、CR2、NEF、JPG/JPEG；Bridge、Lightroom 与直接打开 exe 均一致。全部文件都不支持时提示重新选择。文件树数量靠右对齐，滚动条独占右侧空间；拖到可用文件夹时显示移动光标和蓝色边框，同一文件夹、排队照片或不可用目标显示禁止光标和红色边框。

在 PowerShell 7 运行 `./scripts/install-bridge.ps1`，重新启动 Bridge 并启用 FastCull 启动脚本。选中支持的照片、一个或多个文件夹后，右键或“工具”菜单里的 **FastCull · 打开选片器** 均可启动。文件夹会递归加载子目录中的支持照片，允许混选照片与文件夹；重叠目录自动去重。多个照片目录会自动显示文件树。当前机器已安装到 Bridge 2025 / 2026 用户脚本目录。

Bridge 直接读取与修改 XMP，必要时按 F5 刷新；关闭框为直接关闭/取消。LR 重载插件后，在插件命令菜单展开时按 **F** 可启动（菜单助记键）。宿主支持范围与安装说明见 [BRIDGE.md](docs/BRIDGE.md)。

Bridge 模式支持实际移动 ARW/CR2/NEF 及对应 XMP/ACR，也支持携带内嵌元数据的 JPG：Ctrl／Shift 多选后拖到文件夹，或点“移动”选择目标；目标也可粘贴其他文件夹路径。按 **M** 移到上次位置，首次按 M 先选择目标。默认“移动后下一张”，支持连续整理及后台批量队列；同名文件不覆盖。LR 模式仍保存整理计划。详见 [文件夹操作说明](docs/FOLDERS.md)。

## Lightroom 工作流

1. 在图库中选中照片，可以 Ctrl+A 全选当前文件夹。
2. 图库 → 增效工具额外命令 → **打开 RAW/JPEG 选片器（读取 LR 评分）**。
3. 批量读取 LR 元数据后立即分离启动窗口，照片元数据初始化在后台进行，窗口显示进度与失败计数。当前照片初始化完成后才允许评分；后台任务只初始化一次，不覆盖后续选片修改。
4. 在选片器里选片，RAW 改动原子写入同名 `.xmp`，JPG 改动原子更新内嵌 XMP。保存失败会在窗口顶部显示原因，不会把未保存状态当成成功。
   - 元数据初始化失败时仍显示图片，评分暂不可用；修复旁车或权限后按 **R / 重试**。图像各分辨率的失败互不阻断。
5. 选择 **同步全部并关闭**：退出主窗口后等待仍打开的 RAW 窗口完成保存回执，再由 LR 自动同步本次修改的星级、颜色、旗标、曝光、白平衡、基础调整、裁切和旋转。有整理计划时显示 **同步并整理后关闭**：同步上述字段后建立 LR 待整理分组，实际移动在 LR 原生完成。**仅关闭，稍后同步**保留修改及计划，**取消**继续选片。按原会话 UUID/路径定位，不依赖 LR 当前选区。
6. 同步失败或选择稍后同步时，使用 **同步选片会话（仅修改过的字段）** 重试。仅写入本会话修改的字段，保留其他显影设置；旋转使用绝对目标方向，重试不会重复旋转。已同步的字段不会再次写入，之后的新修改仍能同步。详见 [退出同步说明](docs/LR-SYNC.md)。
7. 若需手动读取当前选区元数据字段，使用 **同步选中照片（读取照片元数据）**，同时支持 RAW 旁车与 JPG 内嵌 XMP；此命令包含有效曝光、白平衡、基础调整、裁切和方向，使用 Rust XML 解析器。独立打开 exe 或从 Bridge 打开时没有 LR 会话，关闭框显示直接关闭/取消。

会话清单保存在 SDK `appData/FastCull/sessions/`（由 `getStandardFilePath('appData')` 返回平台目录，无法使用时回退 `appPrefs`），待同步会话的目录身份、原照片 UUID/路径和同步进度由插件偏好保存；后台初始化不算用户修改。写入失败、照片移出目录或旁车损坏会报告并保留待同步状态。运行中的会话可同步当前快照，之后的新编辑在下一轮同步；已关闭且完全同步的会话移出待同步列表，磁盘清单保留。多个会话按启动顺序处理；同一路径的 LR 虚拟副本仍共享物理 XMP，进入选片器的初始值按列表最后一项，返回目录时按原选中副本 UUID 定位。

清星、清色和清旗标都能同步。LR 是打开时的状态来源：打开操作会覆盖旁车旧评分。若启用了 LR 自动写入 XMP，请避免同时在两端修改同一张照片。

## 独立使用

在 PowerShell 中运行，或把支持的照片文件/文件夹拖到 exe 上：

```powershell
& './lrplugins/FastCull.lrplugin/fastcull.exe' 'D:/Photos/旅行'
& './lrplugins/FastCull.lrplugin/fastcull.exe' 'D:/Photos/DSC00001.ARW' 'D:/Photos/DSC00002.ARW'
```

独立目录入口只扫描当前层的 ARW/CR2/NEF/JPG/JPEG，不递归；Bridge 文件夹入口会递归。ACR/Bridge 可读取 RAW 旁车或 JPEG 内嵌 XMP 的星级、标签和方向。自定义 `sr:Flag` 通过本 LR 插件同步；ACR/Bridge 不保证识别该自定义旗标。

工具栏和胶片带保留 LR 风格。胶片带左右按钮跳 4 张，网格单击选中、双击放大。

工具栏分为评分/旗标/颜色行与查看/曝光行；星级、颜色和曝光以整组换行。旋转、重试与日志入口收纳到“更多”，说明与快捷键通过悬停提示显示；菜单和筛选输入框使用自己的按键。成功的关闭自动同步不再弹第二个成功提示，失败才报告；已关闭会话的全部字段同步完成后退出待同步列表，有待完成的整理计划则保留。

筛选支持星级等于（多选）、至少、至多；旗标、颜色标签、拍摄日期/时间区间、相机、镜头、ISO、光圈、快门和焦距，以及文件名关键词。同字段多选为“或”，不同字段为“且”；数字范围包含端点，快门支持 `1/250`，日期只填一天时结束条件包含当日。拍摄时间按照片 EXIF 本地时间，不转换时区。缺失元数据可选“未知”，尚未完成索引的照片不冒充未知。侧栏第一次展开后才后台索引拍摄信息；不会在 GUI 出现前读取全部照片的 EXIF。筛选也作用于网格、胶片带及翻片；无结果时停止评分操作。筛选文字输入期间不会触发选片快捷键。

LR 曝光参数在窗口启动后通过 SDK 后台读取，未取得有效值前禁用曝光按钮，不假定为零。三次 +⅓ 累积为一档；保存到 `crs:Exposure2012`，同步时应用到原会话照片。当前只支持现代处理版本的有效曝光值；自动设置未解析或旧处理版本无法提供此值时，曝光按钮保持禁用。多个物理文件相同的虚拟副本仍共享旁车与曝光值。

曝光通过 GPU 在机内 JPEG 上近似呈现，不增加整张 CPU 图像副本；重新打开后也会按当前曝光值显示。机内 JPEG 不能复现 LR 的完整 RAW 显影、其他显影调整或已剪裁高光的恢复，最终效果以 LR 为准。对比时评分与曝光操作作用于蓝框选中的画面；筛选排除任一对比照片后退出对比，保留符合条件的单图。

旋转在原始方向上叠加，并写入**绝对 TIFF Orientation**；四次旋转恢复原方向，重新打开也会读回。LR 退出同步和手动同步均支持方向；需要实际转动照片时要求 Lightroom Classic 11.4 或更新版本，避免旧 SDK 误转其他选中照片的问题。若 LR 与 XMP 镜像状态不一致，会保留未同步记录并报告。

## 性能与保护

- RAW 优先读取元数据和内嵌预览，100% 下预览不足才后台解码传感器数据，不改写 RAW。JPG 只更新元数据，不重压缩图像。
- 全尺寸保持 `zune-jpeg` 解码；缩小至少一半时尝试 Windows WIC 的原生缩小解码，不适用或失败则回退 Rust。SIMD 缩图跳过不透明照片的多余 alpha 运算；图像方向和用户旋转在 GPU 上完成。
- 缩略图、适屏预览、100% 三个等级。适屏优先读取中等内嵌预览，按实际画布像素加 25% 余量，在 1024～4096 长边之间分档选择；100% 保持每份文件真正的全尺寸像素，不足时仍解码传感器。
- 2–4 个图像线程，一个保留给当前主图；最多两个线程同时解码全尺寸图。切图取消未开始的旧任务，复用当前图、邻近图与对比参考图的在途结果，避免重复解码；过远结果淘汰，邮箱仍有界且不阻塞。
- 全尺寸纹理最多 4 张且目标像素预算 300 MiB；适屏缓存 96 MiB、最多 8 张；缩略图预算 64 MiB。适屏按翻页方向预取 2 张，100% 预取 1 张。对比时保护两张照片、暂停额外大图预取；若两张受保护大图本身超过预算，允许保留这两张，预算不是硬上限。
- 元数据使用独立线程及结果队列，失败不会阻止 JPEG 浏览。缩略图损坏可回退大 JPEG，不把缩略图失败当成整张图片失败。
- 适屏图可见且停留 300ms 后，后台预热当前照片全尺寸图，不占用预留的主图线程；快速翻片、网格和对比模式不新增此类预热。缓存未命中时仍需实际解码和上传，预热并不保证所有点击都瞬间显示。
- 筛选统计按变化失效，收起的分组不计算；同一照片首次元数据探测合并，后台索引按有序队列处理，避免逐张扫描整个待处理列表。
- 预算是缓存像素量，**不是进程总内存上限**；解码中的图像、GPU/驱动和 UI 仍占内存。
- XMP 仅修改目标值，保留其他字节。支持属性式、元素式、单/双引号和命名空间别名；新增属性时补齐命名空间。损坏 XML 或非 UTF-8 文件拒绝覆盖。

2.0.1 修复 Python 原型留下的 `sr:Flag` 等已知字段缺少命名空间声明时的启动错误：读取时识别旧字段，写入时补齐声明并更新原属性，不插入重复字段。不覆盖已有命名空间绑定；真正的重复属性或损坏 XML 仍拒绝覆盖。

2.0.2 改为窗口优先、后台评分初始化，使用 LR 批量元数据接口，并修复分离 GUI 继承启动管道句柄导致 LR 等待窗口退出的问题。100% 下左右键始终翻片。本次也更新了 Lua，共用模块可能被 LR 缓存，升级后请在增效工具管理器重新载入插件一次。

2.0.3 增加分级预览、按方向预取、过时结果淘汰、独立元数据加载与重试，以及按会话同步。升级后请重新载入插件，确认新的“同步选片会话”菜单出现。GUI 日志中的 `100% requested/ready` 记录触发到大图进入绘制帧的时间，不包含显示器刷新或硬件呈现延迟。

2.0.4 修复 LR 打开时的‘无法找到本地会话目录’：改用 SDK 支持的 `appData`/`appPrefs`，递归创建目录并检查返回值，插件日志也使用相同路径规则。现有待同步会话继续按原记录路径读取，不搬移或删除。升级后重新载入插件共用 Lua 模块；Rust 浏览/缓存逻辑保持 2.0.3 的实现。

2.0.5 修复‘clear inherited stdio: 拒绝访问 (os error 5)’：Windows 启动改为不继承任何父进程句柄的分离子进程，不再修改 LR 提供的标准流句柄。也覆盖额外隐藏的管道写句柄，避免 LR 等到 GUI 关闭才返回。会话、中文/空格路径和已有选片操作继续可用。

2.0.6 针对真实 LR 单张照片仍需约五秒才出窗口的反馈，移除程序入口的非必需控制台编码调用，并加入完整启动分段计时。记录 LR 菜单入口、异步任务排队、元数据导出、popen、读取返回，以及 Rust 最早入口、日志初始化、窗口/图形初始化、字体和首帧。真实 LR 加速效果需要重新载入后复测，不能用独立命令行的快速返回替代。计时失败不会阻止启动。

2.0.7 根据真实分段日志，将原生 Rust 的打开和同步命令改为 `LrTasks.execute`，等待期间只挂起当前任务，让 LR 的 UI 继续处理消息；命令输出通过唯一临时文件取回，用完清理。旧 Python 回退仍使用原来的执行方式。GUI 启动时向子进程传递 Windows 前台权限，并在窗口可见后请求一次焦点，避免首帧仍隐藏时请求被忽略。不会在后续浏览期间持续抢焦点。升级需重新载入共用 Lua 模块。

2.0.8 改为原生 Windows 前台核验和有限的启动激活，等待窗口可见后激活并核验 `GetForegroundWindow`。必要时仅在发起程序仍处于前台时短暂连接输入线程，并立即断开；最多三次激活、仅限启动 1.5 秒内。用户已确认真实 LR 自动前台正常。该次 340 张打开日志从菜单入口到首帧 489ms、首图 591ms，不代表所有机器的冷启动上限。

2.1.0 加入后台元数据筛选、曝光快调和双片对比，以及关闭确认与自动同步星级。星级有独立同步确认进度；旧 V1 会话仍可读取，曝光使用 V2 会话记录。曝光参数读取和拍摄信息索引均放在窗口启动之后。工具条按行高换行，已检查常规与最小窗口布局。升级后请重新载入整个插件并关闭旧版本选片窗口；新功能的真实 LR 交互仍需用户复测。

2.2.0 增加文件夹树、创建目录和批量整理计划。按已确认的完整保留 LR 数据方案，有计划时确认退出会先同步照片修改，再建立 LR 待整理分组；实际移动由 LR 原生拖动完成。完成一组后“同步选片会话”核对路径并定位下一组。详见 [文件夹操作说明](docs/FOLDERS.md)。保留 2.1.2 的相对联动和关闭框布局；核对表及真实 LR 验证边界见 [需求与交互核对](docs/UI-ACCEPTANCE.md)。

## 日志和 CLI

Rust 程序日志默认在 `%LOCALAPPDATA%/FastCull/logs/`；LR 插件日志在 SDK `appData/FastCull/logs/`（必要时回退 `appPrefs`）。记录解码失败、首次主图布局尺寸、旁车写入和 panic 堆栈。GUI 启动失败会提示日志位置；无头命令失败直接输出错误并返回非零退出码，不弹窗。日志保留供排错；本版本不自动删除历史日志。

```text
fastcull.exe --open <statefile>        立即分离启动窗口，后台写旁车
fastcull.exe --apply-state <statefile>  只写旁车
fastcull.exe --from-state <statefile>   从列表启动窗口
fastcull.exe --open <statefile> --session <manifest> --session-id <ID>  打开并记录本会话修改
fastcull.exe --sync-session <manifest> [after-revision [stars-ack]]  读取本会话的新修改
fastcull.exe --sync-stars <manifest> [after-revision]  仅导出本会话修改的星级
fastcull.exe --read-sidecars <statefile>  用 Rust 读取指定照片的旁车字段
fastcull.exe --inspect <ARW>           检查 JPEG 范围、方向、EXIF
fastcull.exe --benchmark <ARW> [runs]   含 CPU 方向变换的解码基准
fastcull.exe --benchmark-sensor <ARW> [runs]  GUI 原始像素解码基准（不含 GPU 上传）
```

桥接状态文件为 UTF-8，每行 `path|rating|label|flag`；空字段清除，缺失字段保持。`--apply-state` 输出实际 `RESULT wrote=N kept=N error=N`。2.0.2 的 `--open` 返回 `RESULT wrote=0 kept=0 error=0 pending=N` 与 `RESULT launched=1`，表示后台队列已交付，不表示已完成写入；最终统计在窗口/日志中。`--open` 使用独立临时快照，父进程返回后不会因另一轮打开覆盖列表而影响子窗口。插件采用唯一状态文件名。

## 从源码构建和验证

需要 Rust 1.90+、Visual Studio C++ Build Tools、PowerShell 7。构建配置固定 Windows x64，静态链接 C 运行库。

```powershell
pwsh -File scripts/build.ps1         # release 构建并复制进插件
pwsh -File scripts/build.ps1 -Test   # Rust 核心与 CLI 回归
cargo clippy --all-targets --locked -- -D warnings
```

Python 仅供开发验收：`tests/test_bridge.py` 需要 `lupa`，样片对拍需要 Pillow；运行 `scripts/verify_samples.py` 与 `scripts/native_smoke.py` 时显式指定样片目录和新建的 `--scratch` 目录。用户运行插件无需这些依赖。

启动句柄回归使用 `scripts/launch_probe.py --exe <exe> --scratch <新的隔离目录> --mode invalid-stdin`；另两种模式为 `extra-pipe`、`normal`。测试使用自生成 ARW，检查管道快速 EOF、实际窗口绘制及关闭会话，不操作 LR 目录。各模式顺序运行，避免 GUI 键盘注入相互干扰。

分段日志分析：`python scripts/analyze_startup.py --plugin-log <LR插件当天日志> --rust-logs <Rust日志目录> [--session <ID>] [--output <JSON>]`。脚本只读取日志，不访问照片或修改 LR。旧版 LR 日志只有整秒，因此报告等待区间；新版将 SDK 的 Cocoa 时钟换算为 Unix 毫秒，按会话 ID 关联启动进程与 GUI 进程，分别报告排队、popen 等待、入口至首帧等时间。

构建与测试缓存统一放在 `.agent-temp/2026-10-12-rust/`，正式 exe 和分发包不依赖它。第三方许可随插件附带 `THIRD-PARTY-NOTICES.txt`。
